2. Migration: server/prisma/migrations/20260914000000_lab3_requester_regression/
   - CREATE TABLE "PublicComment" (+ index, + RESTRICT FKs to Ticket/User)
   - DROP TABLE "DevRequester"

   Safe / non-destructive for ticket data: the previous migration
   (20260913000000_lab3_auth_and_authorization) had already re-pointed every
   Ticket.requesterId / Attachment.uploadedByRequesterId / removedByRequesterId
   from DevRequester.id to User.id (recorded in
   evidence/lab-03/auth-and-authorization/migration-data-preservation.txt), so
   "DevRequester" no longer owned any rows when it was dropped.

   Verification AFTER the migration (psql against the local dev DB):
     SELECT count(*) FROM "Ticket";                                            -- 10
     SELECT count(*) FROM "Ticket" t LEFT JOIN "User" u
       ON u.id = t."requesterId" WHERE u.id IS NULL;                           -- 0 orphans
     SELECT count(*) FROM "Attachment" a LEFT JOIN "User" u
       ON u.id = a."uploadedByRequesterId" WHERE u.id IS NULL;                 -- 0 orphans
     SELECT count(*) FROM "PublicComment";                                     -- 4 (seeded)
     SELECT to_regclass('public."DevRequester"');                              -- NULL (dropped)
