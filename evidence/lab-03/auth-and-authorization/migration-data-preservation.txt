Conversion performed by the hand-written SQL:
  1. CREATE TYPE "Role", CREATE TYPE "TicketStatus"; ALTER TYPE "ItPriority" ADD VALUE 'URGENT'.
  2. CREATE TABLE "User" + unique index on email.
  3. INSERT Users from DevRequester (one Requester account per distinct dev requester).
  4. Ticket.requesterId Int(DevRequester) -> TEXT(User): added a temp column, backfilled by
     joining DevRequester.email = User.email, then dropped the old column and FK and renamed.
     A DO $$ ... RAISE EXCEPTION guard aborts the migration if ANY ticket would be orphaned.
  5. itPriority NULL values backfilled from requestedPriority, then SET NOT NULL + DEFAULT 'MEDIUM'
     (BR-14 semantics: IT Priority starts equal to Requested Priority).
  6. currentStatus renamed to status and cast to TicketStatus (values carried across, not dropped).
  7. ticketOwnerId (unused Int column) replaced by ownerId TEXT -> User; new indexes on
     status / ownerId added and the requesterId indexes recreated.
  8. Attachment.uploadedByRequesterId / removedByRequesterId converted the same way
     (0 rows existed, but the migration handles them with the same orphan guard).
  9. DROP TYPE "CurrentStatus".
