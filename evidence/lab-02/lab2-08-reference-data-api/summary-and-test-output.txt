Originally, lab2/08 was flagged for fixing known issues with the reference-data
API endpoints (wrapped response format, auth middleware for categories and
related-systems). Investigation found these issues were already resolved in
lab2/05 (see specification.md §11 items 7–8).

Scope was therefore changed to cleanup (per specification.md §11 item 21):

  (a) Added inactive-filtering test coverage for both GET /api/categories and
      GET /api/related-systems — each test creates an isActive=false record via
      Prisma, asserts it is excluded from the API response, and cleans up the
      record. This closes a regression-risk gap where removing the
      isActive: true filter in the handler would go undetected.

  (b) Deleted client/src/api.ts — a Lab 1 leftover (checkSystem() function
      using raw fetch without auth headers, parsing the old bare-array response
      shape). No runtime component imported this file; only a Lab 1 test
      (tests/lab-01/App.test.tsx) dynamically imported it with mocked fetch.
      The Lab 1 checkSystem test block (2 tests) was removed; the 3 App tests
      in the same file were retained.

Additionally, a pre-existing TS2322 type error in
client/src/components/ticket-detail/AttachmentSection.tsx was fixed as part of
this branch (busy/busyLabel props don't exist on Button — changed to
variant={isUploading ? "busy" : "primary"}).
